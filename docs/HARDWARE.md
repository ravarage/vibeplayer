# Hardware and compatibility

Vibe Player has been developed and tested on exactly one device. Everything else below is either
a reasoned expectation or marked untested.

## Best (the reference device)

POCO X5 Pro 5G (codename redwood), Snapdragon 778G, Adreno 642L, 8 GB RAM, Android 17 (a custom build;
the project owner is porting a Vulkan 1.3 driver to it).

- Hardware decoding through MediaCodec for H.264, HEVC (including 10-bit HEVC 4K in the test clips) and VP9.
- AV1 is decoded in software with dav1d (the 778G has no AV1 hardware decoder). 10-bit H.264 (Hi10P) also
  falls back to software.
- Per-format configuration chosen before opening (P6-07), from the data table `player/src/main/assets/format_table.json`
  keyed by the Vulkan driver hash (P6-06; generated by `tools/bench/make_table.py`, see ARCHITECTURE.md). Driver
  `c0b92d25178c8b21` (P6-08, on battery):
  - H.264 8-bit: MediaCodec copy-back with Vulkan `vo=gpu-next` (549 mA vs 637 mA GLES zero-copy, 0 drops on all;
    zero-copy also stalls at start, B-08). Without Vulkan: copy-back on GLES `vo=gpu`.
  - Any MediaCodec clip above 2560x1440 (4K): zero-copy on OpenGL ES, whatever the table row says, unless the
    renderer is set to Vulkan. Copy-back cannot carry 4K on this phone (H.264 4K30 8.8 drops/s vs 0.1, HEVC
    10-bit 4K60 47.8/s vs 0; ARCHITECTURE.md, "Copy-back size limit").
  - HEVC 8/10-bit: MediaCodec zero-copy on OpenGL ES (605 mA vs 1254 mA, 29% vs 117% CPU, drops equal within 5%).
  - VP9: MediaCodec zero-copy on OpenGL ES (339 mA vs 794-1026 mA).
  - AV1 (any): dav1d software decode on all cores with Vulkan `vo=gpu` (362 drops vs 385 gpu-next and 918 GLES).
  - 10-bit H.264 (Hi10P): software decode with Vulkan (else GLES).
- Vulkan driver cache: availability is probed and remembered per driver build (keyed by `Build.FINGERPRINT` + `vulkan.adreno.so` mtime; never the 1.1 system feature flag). Format failures on this driver build are remembered so subsequent opens skip Vulkan.
- Safety net fallback chain: Vulkan -> OpenGL ES -> software decoding, preserving playback position with on-screen message and `VULKAN-FAIL` / `GLES-FAIL` logging.
- OpenGL ES 3.2 on the Adreno 642L is the reliable fallback and the measured best renderer for HEVC/VP9 (zero-copy).
- Vulkan: the stock driver reports Vulkan 1.1, which is below libplacebo's 1.2 minimum, so the Vulkan
  renderer cannot start and the app falls back to OpenGL ES. The owner's experimental driver reports
  Vulkan 1.3.295 (`vulkan.adreno.so`); with it the Vulkan renderer plays H.264 and AV1 in short tests.

Software AV1 at 4K is the heaviest case. Measured on this phone in one 20-second test with the debug
overlay's counters (`av1_4k.mp4`, dav1d, all cores, see `ARCHITECTURE.md`, section Vulkan status update):
frames dropped by the output were 565 with OpenGL ES (`gpu-next`), 517 with Vulkan (`gpu-next`) and 359 with
Vulkan (`gpu`), with picture moving in every run. The 60 s power runs below agree (362 to 918 drops a minute).
In other words, 4K AV1 is not smooth on this chip; 1080p AV1 is the realistic target. H.264 1080p had 0 to 7
dropped frames in the same test.

### Measured on the reference device (2026-10-14/15, driver `c0b92d25178c8b21`)

Details and methods in [BENCHMARK.md](BENCHMARK.md).

- **Start time** (release build, Efficient + Auto, intent to first frame, 10 cold opens each): median 882 ms on
  `h264_1080p.mp4` (min 799 ms; one B-08 stall recovered at 5.7 s), median 798 ms on `ichiban.mp4` (783-826 ms).
  About 390 ms of it is mpv opening the file.
- **Memory** (release build, `dumpsys meminfo` TOTAL PSS, phone charging): browser idle 68 MB; 1080p H.264
  playing 2 min 216 MB (428 MB before the cache budget; target 220 MB); 4K AV1 playing 708 MB (dav1d frame
  buffers); mini player 178 MB; browser after closing the player 110 MB.
- **Power** (60 s per row on battery, steady current from `current_now`, screen on, interleaved GLES / Vulkan):

  | Clip | Best configuration | Steady current | Steady drops | Next best |
  |---|---|---|---|---|
  | H.264 1080p | Vulkan `gpu-next`, copy-back | 549 mA | 0 | GLES zero-copy 637 mA, 0 drops |
  | HEVC 10-bit 4K | GLES zero-copy | 605 mA | 1241 | Vulkan `gpu` copy-back 1254 mA, 1207 drops |
  | VP9 1080p | GLES zero-copy | 339 mA | 0 | GLES copy-back 794 mA |
  | AV1 4K (dav1d) | Vulkan `gpu` | 1563 mA | 362 | Vulkan `gpu-next` 1340 mA, 385 drops; GLES 1668 mA, 918 drops |

  For HEVC and VP9, zero-copy on OpenGL ES uses far less power and CPU than any copy-back path; for H.264,
  Vulkan `gpu-next` copy-back measured lowest (and zero-copy stalls at start more often, B-08). The HEVC 4K drops
  in this table are fixed: the decoder now gets an operating-rate hint (device A/B: `operating_rate=120` gave 0
  drops), and since 0.9.0 4K clips skip copy-back (0.0 drops/s zero-copy on GLES `gpu-next`, 2026-10-23).

## Best OS

Android 17 (SDK 37) is the only version tested, and the only one the current build installs on
(`minSdk = targetSdk = compileSdk = 37`).

## Likely to work if rebuilt with a lower minSdk (untested)

Other arm64-v8a phones with OpenGL ES 3.x: Snapdragon, Dimensity, Tensor and Exynos. Nothing in the code
was deliberately limited to the reference device, but the app uses recent Android APIs and was never run
on anything else, so lowering `minSdk` will need code changes and testing. What changes per chip:

- Hardware AV1 decode on newer SoCs: MediaCodec would be used instead of dav1d, if the hwdec list allows it
  (untested).
- Vulkan availability: Vulkan 1.2 or newer is required for the Vulkan renderer. Many recent phones qualify;
  the app tries Vulkan only if the user selects it and otherwise falls back to OpenGL ES.
- 10-bit HEVC and other profiles depend on the vendor decoder; if the hardware decoder rejects a stream the
  software decoder is used.
- CPU speed decides how far software decoding goes (AV1 4K above all). Faster cores than the 778G's will help;
  slower ones will drop frames earlier.

## Will not work

- Anything that is not arm64-v8a: 32-bit ARM phones, x86 / x86_64 emulators, and Chromebooks or PCs without
  ARM translation. The native libraries are built for arm64-v8a only.
- Android below 17 with the published build (minSdk 37).
- Devices without OpenGL ES 3.x.
- The Vulkan renderer on Vulkan below 1.2 (including the stock driver of the reference phone). It falls back
  to OpenGL ES; playback itself still works.
