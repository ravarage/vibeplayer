----- standing rules for agents in this project -----
- Commit your own work: messages start with the task ID ("P5-01: ...", "P7-04 wip: ...", "B-08: ..."), one commit per task or per finished step, ending with the line: Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>. Use `git add <explicit paths>`; never `git add -A` at a repo root, never amend, force, reset, checkout of files, clean or stash. Commit after every finished step so an interruption (usage limits and PC crashes have happened) loses little. If you find uncommitted changes from an earlier interrupted agent in your checkout, inspect them with git diff, keep what is sound and finish it.
- Phone (only when your brief allows it): `export PATH=/home/rava/vibeplayer/tools/bin:$PATH` in every shell command, then plain `adb` (the wrapper prefers Wi-Fi and falls back to USB; the user may unplug the cable at any time; never set ANDROID_SERIAL). If no device: `adb connect $(cat /home/rava/vibeplayer/tools/bin/phone_wifi)` and retry. Before every on-device step run /home/rava/vibeplayer/tools/phone_idle.sh and wait while it exits 1 (the user is using the phone). Run /home/rava/vibeplayer/tools/wake.sh before every on-device check. Run /home/rava/vibeplayer/tools/battery_ok.sh before every on-device step: if it exits 1, stop all phone work at once and report it (the user needs at least 10% battery in the morning). Screenshots: `adb shell screencap -p /data/local/tmp/x.png && adb pull /data/local/tmp/x.png /tmp/vp_<name>.png`, then open the PNG and look at it. Picture check: `python3 /home/rava/vibeplayer/tools/check_video.py`. Never uninstall or clear data of com.vibeplayer (it holds the user's watch history); never touch other packages, phone settings, alarm/ring/notification volume or DND; media volume must stay where it is (the user wants it at 0); never adb kill-server/usb/tcpip/reboot; leave the phone on the home screen. Put a timeout on every adb and gradle command.
- Build: `timeout 900 ./gradlew :app:assembleDebug` (JBR from ~/.gradle/gradle.properties). Unit tests: `timeout 900 ./gradlew :player:testDebugUnitTest :app:testDebugUnitTest`. In worktrees, native/mpv-android is a symlink to the main checkout's tree: never modify or rebuild it.
- Architecture: UI talks to the engine only through PlayerEngine methods and the state/position/stats flows; the PlaybackService owns the engine; no blocking mpv call on the main thread; Room/DataStore/file IO on the IO dispatcher. Features the user relies on must keep working exactly: mini player (PiP) incl. auto-advance inside it, auto-play next, previous/next, resume, remembered tracks per file, folder track memory and default languages, aspect modes, gestures incl. hold for speed, speed, subtitle/audio sync, thumbnails, background playback.
- PROGRESS.md: honest notes; DONE only with acceptance met and evidence you saw. Do not create planning documents.
- Final message: plain text, per task: status set, evidence, commits (short hashes), what is left and what only the user can check.
- Bugs: if you see or experience a bug while working, fix it immediately (separate commit "fix: ...", test if possible); if it is large or in another agent's files, record it for the reviewer. When your task is done, review the code you touched for bugs and fix them (AGENT_RULES.md "Bugs you notice").
